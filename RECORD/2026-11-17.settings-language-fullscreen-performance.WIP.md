## The common part (all the engines with a settings screen)

- **engine-specs `^0.5.0` → `^0.6.0`**. The app imports the helpers from `../engine-specs.js`, the
  runtime copy the Makefile already ships beside the SDK.
- **English and Spanish**:
  - every string of the app (today Spanish, inline) moves into one `{ en, es }` table;
  - the table is read through `host.locale ?? resolveLocale()`;
  - SDK errors stay English and are shown as a detail under the app's own words.
- **Pause menu**: Continuar, the engine's entries, **Ajustes**, **Pantalla completa**, Volver al
  lanzador (UX.md rule 4).
- **Ajustes**: `createSettingsScreen()`.
  - Rows come from `settingsModel()` over the SDK's `config()` / `options()` descriptors (only those
    with a `label`), plus `SHARED_SETTINGS`.
  - A live change is applied at once.
  - A non-live one is saved and passed at the next start; its row says "Se aplica al reiniciar".
  - Choices are saved per engine with `saveSettings('mgba')` and read at mount with
    `loadSettings()`.
- **Fullscreen**: `createFullscreenToggle(root)` (Cmd+Enter / Alt+Enter, Select + Y), plus the
  pause-menu entry.
- **Performance**:
  - `createWakeLock()`, held while playing when "Mantener la pantalla encendida" is on (default
    on);
  - `createPerfCounter()` when "Mostrar rendimiento" is on: fed once per emulated frame where the
    SDK reports frames, else counting display frames.
- **Controls and audio pacing**: per engine, below.
- **Checks**:
  - `make test` / build;
  - in Chromium, with the owner's test ROMs where needed: the pause menu, every setting applied (or
    noted as on restart), saved across a reload, fullscreen by key and by menu, the counter, en / es;
  - a phone width.
- **Release**: minor.

## mGBA

- **Settings**: the 11 catalog rows in `src/mgba.options.ts` (Video / Audio / Emulation: image
  filtering, aspect, interframe blending, volume, system, GB model, BIOS…).
  - They already carry English labels and value labels, and become `label` / `group` /
    `valueLabels` with Spanish added.
  - Rows that need a reset stay non-live.
- **Controls**: feasible.
  - `src/mgba.core.ts` maps `KeyboardEvent.code` → control through `DEFAULT_KEYMAP` /
    `buildKeymap()`.
  - The app lists A, B, L, R, Start, Select and the d-pad, and passes the saved bindings to the
    core.
  - Gamepad buttons: to check how the core reads `getGamepads()`. If it takes a button table, the
    pad is remapped too; if not, only keys, and the row says so.
- **Audio pacing** ("Sincronización"): the core drives its own `requestAnimationFrame` loop
  (`mgba.core.ts`). To check whether that loop can take `createFrameClock()`. If it cannot without
  changing the WASM build, the setting is left out of this release and its record says why.
- **Order**: first of the engines, as the template for the rest (it has the newest package
  layout).

## Walkthrough (2026-11-17 19:40 UTC) — mGBA done (waits for engine-specs 0.6.1)

Adds: what was built, what changed from the plan, and the checks.

**Changed from the plan**:
- **No "Sincronización" row.** The core already paces by the audio clock: each tick it runs the
  frames the audio buffer is short of, with a wall-clock fallback when audio is blocked. A
  display / audio switch would change nothing.
- **engine-specs 0.6.1 is needed.** Bindings had to carry `KeyboardEvent.code`, the physical key
  mGBA binds, and 0.6.0 only stored `KeyboardEvent.key`. That patch is on engine-specs' branch
  (its record, 18:20 and 19:20). This package is at `^0.6.0` for now. **The release waits for
  0.6.1 to be published**, then the pin moves to `^0.6.1`; without it a remapped key would not
  reach the core.

**SDK** (`src/`):
- `mgba.core.ts`:
  - `setControls({ keys, buttons })`, live: keys rebuild the `KeyboardEvent.code` keymap, and
    buttons replace the gamepad table, which was hard-coded until now. The left stick still moves.
  - An `onFrames` hook after each batch of emulated frames.
  - `DEFAULT_KEYMAP` / `DEFAULT_PADMAP` exported.
- `mgba.sdk.ts`: `play.setControls()` (kept across a restart), `play.onFrames(listener)`, and the
  types / defaults re-exported.
- `mgba.options.ts`:
  - Each option's descriptor gets `label` / `group` / `valueLabels`, in English from the catalog
    and in Spanish from a table beside it.
  - Groups: video → Vídeo, audio → Audio, emulation and controllers → Emulación. Debug stays
    internal (no label).
  - Volume's descriptor now lists its menu values as `enum`, so it can be stepped; its range is
    still what values are coerced to.

**App** (`src/app/app.js`, `app.css`):
- **en / es**: every string is in a `STRINGS` table read through `host.locale ?? resolveLocale()`.
  Dates use the locale too.
- **Pause menu**: Continuar, the slots, Reiniciar, **Ajustes**, **Pantalla completa** (its key in
  the hint), Volver al lanzador.
- **Ajustes** (`createSettingsScreen`):
  - mGBA's options plus "Mantener la pantalla encendida" and "Mostrar rendimiento";
  - Controles: A, B, L, R, Start, Select and the d-pad, each with key and button;
  - saved in OPFS `settings/mgba.json`. mGBA's values are handed to the SDK before start; the
    controls go through `play.setControls()`;
  - a live change applies at once; the others are recorded on the running engine and applied by
    Reiniciar or the next start;
  - Restablecer puts the defaults back.
- **Fullscreen**: `createFullscreenToggle(root)` (Cmd / Alt+Enter, Select + Y) and the menu entry.
- **Wake Lock**: held while in game when the setting is on; released in any menu.
- **Counter**: `createPerfCounter(root)`, fed by `play.onFrames`.

**Checks**:

  locally; the WASM was taken from the published `@wasm-gaming/mgba-wasm@0.2.1`.
- In Chromium, on a test host page:
  - The ROM is a homebrew 32 KiB Game Boy image (a counting loop, no logo). The page forces the Game
    Boy core through the saved settings, which also exercises them.
  - The pause menu lists the five entries (es and en). Ajustes shows Vídeo / Audio / Emulación /

  - → on Suavizado changes the canvas's `image-rendering`.
  - "Mostrar rendimiento" shows "55 fps | 18.2 ms (peor 33.2) | 5 perdidos" in game.
  - A takes K, then B takes K and A gets Z (swap). After remapping, the core takes K and no longer
    X.
  - Alt+Enter enters fullscreen.
  - After a reload, Suavizado, the counter and the controls are back (this found the engine-specs
    `parseSettings` fix).
  - At 390px the screen fits, in English.
