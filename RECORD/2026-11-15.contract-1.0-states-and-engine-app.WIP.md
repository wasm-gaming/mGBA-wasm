# Contract 1.0, save-state slots and the engine app — 2026-11-15

Status: **proposal, awaiting approval.**

Same treatment as snes9x-wasm, blastem-wasm and fbneo-wasm (wasm-gaming/snes9x-wasm#1), so the
launcher's GBA entry (play.germade, `engine: 'mgba'`, `status: 'soon'`) can turn on.

## Where mGBA-wasm stands

- Working emulator (GBA, GB, GBC, SGB) on engine-specs 0.2.6's old surface: `load(config)`,
  `manifest`, a typed options catalog with the Escape settings menu, SRAM in OPFS.
- The shim already exposes `core->saveState` / `loadState` (byte-exact, 388 KiB GBA / 70 KiB GB)
  — no C changes needed for states.
- 2D-canvas output (RGBA blit), so `snapshot()` is a plain `toBlob()`.
- Reads keyboard and `navigator.getGamepads()[0]` itself, so the engine-specs touch pad (a
  standard gamepad) already plays — to verify, and to check its GBA/GB layout indices against
  the SDK's mapping (touch: A ← 0, B ← 1).

## Plan

1. **Contract 1.0** — `MgbaSDK` / `MgbaPlay` on engine-specs (^0.5) bases; `MGBA_SPEC` holds
   every default; self-contained ESM (`engine-specs.js` beside the SDK,
   `scripts/localize-specs.mjs`); storage under OPFS `mgba/<namespace>/` (SRAM keeps its file).
   `load()`, the manifest and `emit-manifest.mjs` go. Breaking → 0.2.0.
2. **`play.states`** with blastem's shape: list / get / save / load / copy / lock / remove,
   slots 0–3 + the app's suspend slot 9, `slot_N.state` / `.png` / `.lock`, read into memory at
   start and written through; `pause(owner)` / `resume(owner)` release the keys.
3. **The engine app** (`./app`) — blastem's app (`mgba-` classes): suspend point on start, pause
   menu with the four slots (Cargar focused), Reiniciar, Volver al lanzador; Escape settings menu
   off through the app. Picture 3:2 (GBA) / 10:9 (GB).
4. **Tests + README + demo** as in snes9x-wasm; CI file lists updated.
5. **Verify** — `make test`; end to end in Chromium (iPhone 13 emulation) with a test ROM: touch
   pad → game, pause, save / load a slot, thumbnail. The wasm is built locally (Emscripten) if
   the toolchain is reachable here; otherwise the SDK is checked against the last release's wasm.

Follow-up in play.germade: `RECORD/2026-11-15.gba-on-mgba.WIP.md` there.

## Walkthrough (2026-11-15 17:57 UTC) — what was done

1. **Contract 1.0.** `src/mgba.core.ts` is the 0.1 `load()` moved as it was (loop, audio
   clock, resampling worklet, input, live settings), behind the same `MgbaCore` interface as
   snes9x-wasm's core; `src/mgba.sdk.ts` is `MgbaSDK` / `MgbaPlay` (snes9x's wrapper, with the
   optional `bios` asset and `play.system`). `MGBA_SPEC` in `mgba.options.ts` replaces the JSON
   Schema; the manifest, `emit-manifest.mjs`, `load()`, `setInput()`, `purgeStorage()` and the
   `frame` fps event are gone. engine-specs moved from a 0.2.6 peer to a ^0.5.0 dependency, its
   runtime copied beside the SDK (`scripts/localize-specs.mjs`).
2. **`escMenu` dropped.** mGBA never drew a settings overlay: the 0.2.x demo shell did, and that
   shell is gone. `toEscMenuGroups()` stays exported for a host that wants to draw one.
3. **States.** `play.states` with the shared shape; `loadState` now returns false (instead of
   throwing) for another game's state, and redraws the loaded frame. `snapshot()` is the 2D
   canvas' `toBlob()`. Battery RAM is only written when it changed (`saves` event says so).
4. **Input.** Every connected standard gamepad is merged (was pad 0 only), so the touch pad plays
   next to a physical pad; keys and buttons are released on pause and resume. The touch pad's
   GBA and GB layouts send A=0, B=1 — the SDK's mapping.
5. **The engine app** — snes9x's app (`mgba-` classes), slot frames 3:2 (GBA) or 10:9 (GB).
6. Demo page (no build, `.gba/.gb/.gbc/.sgb/.zip`), `tests/storage-path.test.mjs`, README,
   Makefile (as snes9x-wasm's), CI step names. Version left to the release workflow (minor →
   0.2.0).

**Verified**

## Extension (2026-11-15 22:08 UTC) — emsdk pinned to 7.0.0

snes9x-wasm's release broke when `emscripten/emsdk:latest` moved to 7.0.0 (emcc no longer links
libc++ for C++ objects; wasm-gaming/snes9x-wasm#2). mGBA is C and still builds — checked: the
build script in `emscripten/emsdk:latest` (= 7.0.0) produces `mgba.js` (64 KB) + `mgba.wasm`
(792 KB) — but the image is pinned now to **7.0.0** in `build-main.yml`, `release.yml` and
`build-mgba-docker.sh`, so the next emsdk cannot break a release silently.
